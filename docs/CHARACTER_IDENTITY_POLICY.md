# Permanent character identity policy

The supplied character is the authority. Recreating/redesigning visible eyes, face, hair, costume, ornaments, logos, colors, silhouette, style or distinctive features without user approval is a defect. Hidden sides/back may be inferred only with uncertainty recorded and without contradicting observed evidence.

Evidence states are Observed (direct source evidence), Inferred (generated hypothesis), Unknown (not available), User Approved (explicitly accepted proposal). A reference contains source SHA-256, original canvas, optional original-layer record/channel byte ranges and later pixel/region anchors. Source Provenance is original; preview/working/generated/user-approved data are distinct roles with parent hashes and tool versions.

DEV-02 preserves the original and records layer references, dimensions/color/precision/preview derivation. It does not recognize eyes, costumes or character identity. No semantic anchors are fabricated. A future UserApprovedChange must record the proposal hash, affected observed anchors, explicit approval and reviewer/time, rather than treating an AI confidence score as permission.

Source hash equality proves byte preservation only. It cannot prove that an AI output depicts the same character. DEV-04/05 establish observed regions, DEV-06/12–14 preserve and label inference, DEV-07–24 maintain provenance through rig/export, DEV-20/32 compare identity with visual/expert evidence. Gate B stays unverified until that comparison exists.

Permanent product principles: character identity preservation, beginner minimal-click authoring, and automatic completion of broadcast-ready models. The last principle is a future product target requiring rig/quality/runtime verification, not a capability added by image import. REQ-079–081 own these commitments across later DEV work.
