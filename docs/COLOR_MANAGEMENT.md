# DEV-02 color and alpha scope

Original channel precision, ICC/gAMA/cHRM/sRGB and all metadata remain in unchanged source bytes. The working decoder retains16-bit values; preview quantization to8-bit is an explicitly labelled derivative. Untagged files are assumed sRGB for display and warned as unverified. Custom gAMA/cHRM is preserved and warned; it is not misreported as applied color management.

RGB embedded ICC uses lcms2 Rust6.2.0 with static lcms2-sys4.0.7 (vendored LittleCMS2.19 family), relative colorimetric conversion into sRGB, with row-sized RGB16 temporary buffers. PNG alpha is straight and ICC transforms never modify alpha. For the PSD merged-transparency convention only, white matte is removed in the encoded source space before ICC; alpha-zero hidden RGB is undefined in that composite and is zeroed only in the derivative. Original PSD bytes and layer channels are untouched. RGB hidden under zero alpha is retained through pixel decoding; ICC conversion changes only the derivative RGB. Premultiplied input interpretation and layer recomposition are not implemented. UI checkerboard is a background, not baked into the preview.

Alpha tests include transparent nonzero RGB and half-alpha samples. The same encoded preview can be evaluated over light/dark backgrounds; a cached PSD composite is validated against the stored composite, not an invented Normal-mode substitute. Every special blend identifier is preserved; no unsupported blend is silently relabelled Normal.

A synthetic D65 Display P3 primaries/sRGB TRC profile is tested: P3[255,128,0] converts to clipped sRGB[255,119,0] within2 levels, using independent matrix/transfer expectations from [W3C CSS Color4 conversion equations](https://www.w3.org/TR/2026/CRD-css-color-4-20261007/#color-conversion-code). This is a numeric sample, not comprehensive profile/device certification. Monitor ICC/HDR calibration, WebView/browser pipeline and physical display accuracy are outside the numeric transform guarantee. Generated model fidelity and character identity have separate gates.

LittleCMS [Rust wrapper](https://github.com/kornelski/rust-lcms2) and C core use MIT licenses; license notices must accompany distribution. Audit examined [upstream CubeSize advisory](https://github.com/mm2/Little-CMS/security/advisories/GHSA-4xp6-rcgg-m9qq): bundled source uses pre-multiplication overflow checks and a64-bit accumulator. This is not a claim of no vulnerabilities. Untrusted ICC still requires fuzzing/resource-isolated processing before broad deployment.
